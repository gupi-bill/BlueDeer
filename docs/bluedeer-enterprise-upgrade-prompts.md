> 用法：每次试用喂给超强 Agent **一段**（含开头的「总纲」+ 该段正文）。

## 【总纲 · 所有段共用】

你在接手一个真实运行的多智能体系统 **BlueDeer（忧郁鹿森林公司）**，代码根 `<WORKSPACE_DIR>\BlueDeer`，FastAPI + Python 3.11/3.12，纯原生 HTML/CSS/JS 前端（无前端框架），本地优先。

**项目本质**：一个本地优先、拟人化的多智能体 Agent 生态系统，被设定为「森林公司」，员工是动物智能体（较真松鼠/戒备猬/夜枭猫头鹰/勤恳海狸/狡黠狐狸/绘羽蝶/赤谋狐/针客猬/大坝狸/霜耳兔/土工獾/清音雀/黑卷鸦/天瞰鸢/忧郁鹿总经理）。核心运行时代码在 `core/`，业务模块在 `modules/`，Web 仪表盘入口 `/game/hub`（模板 `templates/project_hub.html`），API 服务 `web_server/`，启动 `uv run uvicorn web_server.app:app --port 8080`。

**现有能力盘点（你改造的起点）**：
- 6 套 agentic 框架已接入 Harness/EventBus：AutoGPT / BabyAGI / CrewAI / LangGraph / AgentGPT / OpenDevin（`core/agentic_loop.py` 等）

- 现有文档：`docs/`（架构/调度/事件总线/安全审查/技术债）、`SYSTEM_PROMPT.md`、`AGENTS.md`

**能力边界（重要）**：你只能处理纯文本。你**看不到图片、不生成图片**。因此：
- 所有验收证据必须是**文本/代码形式**：curl 输出、HTML 源码、CSS/JS 检查结果、断言脚本 stdout、日志文件片段。

**铁律（违反即失败，任何段都要遵守）**：

# ============ 第 1 段 · 平台底座与安全治理（企业化的地基） ============

**本段目标**：把 BlueDeer 从「本地演示工具」升级为「可多人、可审计、可上线」的企业级平台底座。所有改动以 `core/`、`web_server/`、`data/` 为主。

## 1.1 身份与访问控制（IAM）
- [ ] 把现有 `core/auth.py`（硬编码 admin/bluedeer888）升级为完整账号体系：用户表（SQLite）+ 密码哈希（bcrypt/argon2）+ 会话 token（JWT 或服务端 session，带过期/刷新）。
- [ ] 角色权限模型 RBAC：预置角色 `超级管理员 / 管理员 / 运维 / 只读 / 访客`，每个菜单/API 有权限点，前端侧边栏按角色动态显示菜单。
- [ ] 默认账户强制改密：首次登录必须改密码；弱密码拒绝。
- [ ] 登录失败锁定：连续 5 次失败锁 15 分钟，有日志有告警。
- 验收：新增用户→分配角色→登录→不同角色看到不同菜单；错误密码 5 次被锁；`/api/auth/*` 全链路可用；旧 admin 密码失效。

## 1.2 审计与合规
- [ ] 全面审计：`core/audit.py` 扩展为「不可篡改审计日志」：谁、何时、从哪个 IP、做了什么操作（登录/配置修改/任务下发/模型切换/权限变更），写入独立 `data/audit_log.db`，带 SHA-256 哈希链（每行哈希含上一行哈希，防篡改）。
- [ ] 操作留痕进 UI：管理后台新增「审计日志」页（筛选：用户/时间/动作类型），只读。
- [ ] 敏感操作二次确认：删除、清库、改权限、导出数据需二次确认弹窗 + 记录审计。
- 验收：做 10 个操作后，审计页按用户/时间可查可筛；篡改任一历史行后哈希链校验失败（提供校验命令）；UI 有二次确认。

## 1.3 密钥与配置安全
- [ ] 密钥集中管理：新建 `core/vault.py`，所有 API key / token / 密码统一存 `data/vault.json`（字段级加密，主密钥在 `data/.master_key` 或环境变量 `BLUEDEER_MASTER_KEY`），禁止明文散落。
- [ ] 配置文件脱敏：`config.py` 输出/日志/API 返回中所有密钥自动打码（`sk-***`）。
- [ ] 现有硬编码密钥迁移：扫描全库硬编码密码/token，迁移进 vault（至少处理 `web_server/app.py` 的 ADMIN_PASS、OpenClaw 网关 token 引用、`data/model_settings.json` 的 api_key）。
- 验收：`vault.py` 可加解密；日志/接口响应无明文密钥；grep 全库无新增明文密钥；提供迁移脚本且不影响现有功能。

## 1.4 API 网关与限流
- [ ] 统一 API 网关中间件：全站 `/api/*` 请求记录（方法/路径/耗时/状态码/用户/IP），支持按用户+IP+接口 3 层限流（滑动窗口），超限返回 429 + 提示语。
- [ ] 新增 `core/api_rate_limit.py`（用现有 `sliding_window.py` / `token_bucket.py` 复用），限流规则可配置（`data/rate_limits.json`）。
- [ ] API 版本化：现有接口保持兼容，新增接口挂 `/api/v2/` 前缀，响应统一包一层 `{code,msg,data}`（旧接口不动，提供 v2 迁移清单）。
- 验收：ab/脚本连打 100 次被限流返回 429；限流规则改配置即生效；v2 接口有 swagger 文档（`/docs` 可看）。

## 1.5 数据持久化与备份
- [ ] 备份策略正式化：`core/backup.py` 升级为「定时 + 手动 + 保留策略」：每日自动全量备份（SQLite + data/ + 关键配置），保留最近 7 份，可一键恢复；备份任务在 UI「基础设施 → 备份」可见可触发。
- [ ] 数据库完整性：新增 `core/db_health.py` 定期 `PRAGMA integrity_check` + 自动 WAL 模式，异常告警。
- [ ] 敏感数据清理：提供「数据保留策略」配置（日志/会话/审计保留天数），到点自动清理，符合企业合规。
- 验收：手动触发备份成功且能恢复（模拟删一条数据→恢复→数据回来）；UI 可看备份列表；integrity 检查日志正常。

## 1.6 安全加固收尾
- [ ] 中间件补齐：请求体大小限制、CSP 头、X-Frame-Options、速率限制合并、非法路径拦截。
- [ ] 安全自检工具：`scripts/security_scan.py` 扫描依赖已知漏洞（读 requirements.txt 比对）、扫描明文密钥、扫描开放调试接口（/debug 需鉴权）。
- [ ] 输出 `docs/SECURITY_REPORT_ENTERPRISE.md`：汇总本次修复项 + 残余风险 + 加固建议。
- 验收：扫描脚本零高危；/debug 无鉴权访问被拒；安全报告成文。

# ============ 第 2 段 · Agent 生产化与任务编排（企业化的引擎） ============

**本段目标**：把 Agent 从「跑得起来」升级为「扛得住生产」：生命周期、会话、上下文、人机协同、技能体系、任务编排、自愈、成本治理。

## 2.1 Agent 生命周期与版本管理
- [ ] Agent 注册中心扩展：`core/agent_registry.py` 增加「状态机」：`草稿 → 审核中 → 已上线 → 已下线 → 已停用`，上下线记录审计。
- [ ] Agent 版本管理：每次修改技能/提示词/模型配置自动生成版本号（v1.0.0），支持一键回滚到上一版本；版本差异可对比。
- [ ] Agent 健康档案：`core/agent_health.py` 扩展为「健康分」（成功率/延迟/错误率/资源占用加权），健康分低于阈值自动告警 + 自动重试降级。
- 验收：可创建 Agent→改配置→生成 v1.0.1→回滚 v1.0.0；健康分在 UI「代理」页可视化。

## 2.2 会话与上下文管理（生产级）
- [ ] `core/session_store.py` 升级：会话持久化到 SQLite，支持「断点续聊」（重启后恢复）；会话自动压缩策略（超长上下文自动摘要，保留最近 K 轮 + 长期记忆，可配置）。
- [ ] 上下文治理：每个 Agent 独立工作区隔离（现有），新增「上下文使用率」指标（当前 token / 上限），超 80% 自动压缩，超 95% 强制归档。
- [ ] 会话导出：UI「会话」页支持导出单会话（Markdown/JSON）、批量导出、删除会话（二次确认+审计）。
- 验收：杀掉服务重启→会话可续聊；长对话自动压缩生效（观察 token 指标回落）；导出文件格式正确。

## 2.3 人机协同（HITL）
- [ ] 审批流：`core/hitl_manager.py`（已有雏形）补全为通用审批：任务可配置「执行前需审批」/「高危操作需审批」，审批动作（同意/驳回/改派）进审计，审批通知推送（WebSocket + 系统通知）。
- [ ] 确认-执行模式：Agent 在执行「删除/支付/外发/写生产配置」等敏感动作前，必须向用户请求确认，用户确认后才执行。
- [ ] UI：管理后台新增「待审批」中心（待办列表、审批历史、超时自动驳回策略）。
- 验收：创建带审批的任务→出现在待审批→同意后执行/驳回后终止；敏感动作不确认不执行；审计有记录。

## 2.4 技能（Skills）体系企业化
- [ ] 技能包标准化：`modules/` 下每个技能定义 `skill.yaml`（名称/版本/描述/参数 schema/权限要求/所需模型能力），与现有技能注册打通。
- [ ] 技能市场：`core/plugin_manager.py` + `plugin_repo.py` 升级为「技能市场」：可浏览、搜索、安装/卸载、启用/禁用、版本升级，技能来源支持本地目录 + 远程 Git 仓库（可选）。
- [ ] 技能权限隔离：技能可声明所需权限（只读/写文件/联网/执行命令），运行时按最小权限执行，越权拒绝并审计。
- 验收：UI「技能」页可浏览已装技能（数量/版本/启用状态）；可安装本地新技能包；越权技能调用被拒且有日志。

## 2.5 任务编排增强（DAG 生产化）
- [ ] `core/task_orchestrator.py` + `task_dag.py` 增强：DAG 支持「条件分支」（节点根据结果走不同路径）、「重试策略细分」（指数退避/固定间隔/不重试，按节点配置）、「超时熔断」按节点独立配置。
- [ ] 优先级与队列：任务支持优先级（P0-P3），P0 抢占；队列深度可视化（`task_board.py` 增强），背压时自动限流新任务。
- [ ] 幂等与去重：任务带 `idempotency_key`，重复提交直接返回原结果；死信队列（已有 `dead_letter_queue.py`）补全重放/丢弃/标记人工处理。
- [ ] 任务模板库：`task_templates.py` 扩展为模板市场（常用流水线一键套用，如「代码审查流水线」「数据清洗流水线」），模板可版本化。
- 验收：构造条件分支 DAG 跑通两分支；P0 任务插队执行；重复提交不重复执行；UI「工作流」可视化能看到分支/重试/死信状态。

## 2.6 自愈与降级（生产可靠性）
- [ ] `healer_engine.py` 补全自愈策略库：任务失败 → 自动重试 → 退避 → 换 Agent → 换模型 → 降级结果；每层都有日志和告警。
- [ ] 熔断可视化：`circuit_breaker.py` 状态（关闭/半开/打开）在 UI「节点/基础设施」页实时显示，手动可开/关/重置。
- [ ] 混沌自测：`scripts/chaos_test.py` 注入故障（杀任务/断模型/超时），验证自愈链路，输出测试报告。
- 验收：断掉主模型 → 系统自动走 fallback 链并在 UI 显示降级；熔断器状态可视化；chaos 测试报告有结论。

## 2.7 成本与 Token 治理
- [ ] `core/token_auditor.py` + `token_budget.py` 补全为「用量中控」：按 Agent/任务/时段统计 token 与费用（本地模型按 token 计，云端按价目表计），每日/每月预算阈值，超阈值自动降级（切本地模型 / 拒发任务 / 告警）。
- [ ] 成本报表：UI「使用情况」页新增图表：日/周/月用量波形图、按 Agent 占比、按任务类型占比、预算消耗进度条。
- [ ] 用量预警：预算 70%/90%/100% 三级告警，推送 WebSocket + 通知中心。
- 验收：造一批任务后用量页图表正确；设置低预算 → 超阈值自动降级/拒发；告警能收到。

# ============ 第 3 段 · 可观测性、知识治理与企业级 UI（企业化的门面） ============

**本段目标**：让 BlueDeer 看起来、用起来都像一个企业产品：全链路可观测、知识库治理、高端统一 UI、移动端可用。

## 3.1 全链路可观测（Metrics / Logs / Traces）
- [ ] 指标采集：`core/metrics_collector.py` + `observability.py` 补全统一指标：任务吞吐、成功率、时延分位（p50/p95/p99）、队列深度、token 速率、Agent 健康分、模型调用次数；每 10s 聚合存 SQLite。
- [ ] 链路追踪：`core/tracer.py` 补全：任务 → Agent → 模型调用 → 工具调用全链路 trace，UI「调试」页火焰图展示（现有 `/debug` 复用），支持按 trace_id 搜索。
- [ ] 日志中心：`core/log_viewer.py` 补全：全模块日志统一接入（滚动文件 + SQLite），UI「日志」页支持按级别/模块/关键字/时间筛选、实时 tail（WebSocket）。
- [ ] 告警中心：`core/alert.py` 补全规则库：失败率、队列积压、预算、健康分、熔断触发、审计异常；规则可配置（阈值/窗口/渠道），告警历史留痕，支持静默期。
- 验收：跑 100 个任务后，指标页图表正确；火焰图能按 trace 展开；日志页筛选/tail 可用；触发一条告警规则能收到通知且历史可查。

## 3.2 知识库与 RAG 治理
- [ ] `core/rag.py` + `vector_browser.py` 升级：文档接入支持 Markdown/PDF/TXT/Code，自动切块 + 向量化（本地 embedding，Ollama 或轻量本地模型），入库「知识库」。
- [ ] 知识库管理 UI：「资料库」页可上传文档、查看索引状态、搜索测试、删除重建索引、设置「每 Agent 可访问的知识空间」。
- [ ] 引用溯源：RAG 回答必须带引用来源（文档名/位置），可点击跳转原文；无引用时明确标注「未检索到相关知识」。
- [ ] 知识权限：不同 Agent/角色只能检索授权知识空间（与 RBAC 打通）。
- 验收：上传一份 Markdown → 索引成功 → 提问能命中并带引用；未授权 Agent 检索被拒；搜索测试页可验证。

## 3.3 企业级 UI 统一改造（重点）
- [ ] 设计规范落地：以 `templates/project_hub.html` 为主阵地，全站统一「浅色高端卡片风」：浅灰白底 `#F5F7FA`、白卡 `#FFFFFF` 圆角 12、柔和阴影、绿色状态点、品牌蓝 `#1E6FFF` 点缀；深色模式保留可切换。
- [ ] 概览页（首页）重做为企业级指挥舱：顶部 4 大 KPI 卡（在线 Agent / 运行中任务 / 今日 Token / 系统健康分）+ 中部图表（任务吞吐折线 + 用量面积波）+ 右侧实时事件流；所有数字来自真实 API，10s 自动刷新。
- [ ] 全部 14 个模块页统一组件化：状态点、统计卡、图表、表格、徽章、空状态、加载态、错误态八件套统一；移动端（<768px）自适应：侧边栏抽屉化、卡片单列、图表自适应。
- [ ] 新模块补齐：「审批中心」「审计日志」「告警中心」「知识库」「技能市场」「备份中心」等新页面全部挂入侧边栏并可导航。
- [ ] 用户中心：右上角用户菜单（个人信息/改密/退出登录/我的角色），与 1.1 的 IAM 打通。
- 验收：全站**文本级走查**——curl 拉取每个页面 HTML，检查：无 emoji 装饰冗余（正则扫 emoji 字符）、无错位（容器嵌套/闭合合法）、无英文残留界面文字（提取可见文本断言，代码/路径除外）；移动端样式用媒体查询断言（`@media(max-width:768px)` 规则存在且关键容器改单列）；新页面都能从侧边栏进入（侧边栏有对应 `data-view` 且路由 200）且数据来自真实 API。

## 3.4 通知与消息中心
- [ ] `core/notifier.py` 补全统一通知中心：WebSocket 实时推送 + 站内通知（未读数/已读/清空）+ 可选渠道扩展（邮件/webhook/飞书等，仅做适配层留接口，不强制接入）。
- [ ] 通知分类：系统告警 / 审批待办 / 任务结果 / 用量预警，各自开关；右上角铃铛图标 + 未读角标。
- 验收：触发一条告警 → 右上角角标 +1 → 打开可见 → 已读清空；WebSocket 断开重连后仍能收到。

## 3.5 部署与运维
- [ ] 一键启动：`scripts/start_all.py`（或 bat/ps1）一键拉起 BlueDeer + Ollama 检查 + 健康检查；`scripts/stop_all.py` 优雅停机（先停任务再停服务，落盘所有状态）。
- [ ] 健康检查页：UI「基础设施 → 服务状态」显示 BlueDeer / Ollama / 网关 / 数据库各组件在线状态 + 版本 + 最近心跳，异常标红。
- [ ] 升级与回滚：提供 `scripts/upgrade.py`（备份 → 拉取更新 → 迁移 → 验证 → 失败自动回滚）与使用文档 `docs/ENTERPRISE_OPS_GUIDE.md`。
- 验收：一键启动脚本可在干净环境拉起全部服务；优雅停机后无脏数据；模拟升级失败能自动回滚。
