# 架构决策记录（ADR）索引

## 什么是 ADR

架构决策记录（Architecture Decision Record）用于记录项目中的重大技术决策，包括决策背景、选项、结果和影响。

## ADR 列表

### ADR-001：多智能体架构选型

- **状态**：已采纳
- **日期**：2026-08-04
- **决策**：采用多智能体（Multi-Agent）架构，每个 Agent 负责特定角色
- **背景**：BlueDeer 需要模拟森林生物圈的复杂交互，单一 Agent 难以覆盖所有场景
- **选项**：
  1. 单体 Agent + 工具调用
  2. 多智能体协作（角色分离）
  3. 微服务架构
- **结果**：选择多智能体协作，每个 Agent 有独立角色、记忆和工具集
- **影响**：增加了系统复杂度，但提高了可维护性和可扩展性

### ADR-002：事件驱动通信

- **状态**：已采纳
- **日期**：2026-08-04
- **决策**：使用 EventBus 作为 Agent 间通信机制
- **背景**：Agent 间需要异步、解耦的通信方式
- **选项**：
  1. 直接调用（紧耦合）
  2. 消息队列（Kafka/RabbitMQ）
  3. 内存 EventBus（轻量级）
- **结果**：选择内存 EventBus，支持通配符订阅和优先级调度
- **影响**：简化部署，但跨进程通信需要额外方案

### ADR-003：向量检索增强（RAG）

- **状态**：已采纳
- **日期**：2026-08-04
- **决策**：使用 RAG 系统增强 Agent 知识检索
- **背景**：Agent 需要访问项目规范和历史经验
- **选项**：
  1. 全文检索（Elasticsearch）
  2. 向量检索（Embedding + VectorStore）
  3. 图数据库（Neo4j）
- **结果**：选择向量检索，支持三层知识库（global/agent/task）
- **影响**：需要 Embedding 模型，但语义匹配效果更好

### ADR-004：梦境记忆进化

- **状态**：已采纳
- **日期**：2026-08-04
- **决策**：实现梦境记忆自主进化系统（四阶段流水线）
- **背景**：Agent 需要从任务结果中学习和进化
- **选项**：
  1. 简单日志记录
  2. 记忆评分系统
  3. 梦境模拟进化（浅睡→REM→深睡→噩梦）
- **结果**：选择梦境模拟进化，支持质量分级和噩梦告警
- **影响**：增加系统复杂度，但实现了自主知识进化

### ADR-005：任务编排器 DAG

- **状态**：已采纳
- **日期**：2026-08-04
- **决策**：使用 DAG 进行任务编排和并行执行
- **背景**：复杂任务需要依赖管理和并行执行
- **选项**：
  1. 简单队列（FIFO）
  2. DAG 编排
  3. 工作流引擎（Airflow）
- **结果**：选择 DAG 编排，支持拓扑并行和失败传播
- **影响**：适合中小规模任务图，需要手动管理依赖

### ADR-006：FastAPI 作为 Web 框架

- **状态**：已采纳
- **日期**：2026-08-04
- **决策**：使用 FastAPI 构建 REST API 和 Web 服务
- **背景**：需要高性能、异步支持的 Web 框架
- **选项**：
  1. Flask
  2. FastAPI
  3. Django
- **结果**：选择 FastAPI，原生异步、自动文档、类型安全
- **影响**：提高开发效率，但需要 Python 3.7+

### ADR-007：本地优先部署

- **状态**：已采纳
- **日期**：2026-08-04
- **决策**：优先本地部署，支持离线运行
- **背景**：数据敏感，需要离线能力
- **选项**：
  1. 纯云端部署
  2. 混合部署（云端 + 本地）
  3. 本地优先 + 云端可选
- **结果**：选择本地优先，Ollama 本地推理，可选云端同步
- **影响**：降低延迟，保护隐私，但需要本地硬件支持

## 如何添加新 ADR

1. 创建新文件：`docs/adr/NNN-标题.md`
2. 使用标准 ADR 模板：
   - 状态（提议/已采纳/已废弃/已 superseded）
   - 日期
   - 决策
   - 背景
   - 选项
   - 结果
   - 影响
3. 更新本索引文件
